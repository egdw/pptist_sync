# 开发核对：原主题入口 HTML 接入

## 保持不变

- `/upload`、`/play` 的 PPT/PDF 逻辑和 Editor。
- 原 ShowFlow Controller、WebSocket 服务器、角色 `secondary`、`NAVIGATE/ACK/SYNC_STATE` 协议。
- LCD 的 `LcdSceneState`、`led-display/1.0` Payload、revision/SHA256 与 MQTT Topic。
- 原 CSS ZIP 的资源白名单和 theme.css 要求。没有把 HTML 作为 CSS 执行。

## 扩展原流程

| 入口 | 行为 |
|---|---|
| POST `/api/studio/themes/upload` | 原入口。`X-Filename` 为 URL 编码文件名，raw body；新增 HTML/HTM 分支，ZIP 继续原逻辑。 |
| POST `/api/studio/themes/:id/preview` | 原入口。CSS 或 HTML 都只更新 Draft。 |
| POST `/api/studio/publish` | 原发布入口。沿用主题库/Draft/Active/历史生命周期。 |
| GET `/api/studio/themes/current/download?scope=draft` | 下载选中的类型；HTML 为原始字节，CSS 为原主题 ZIP。 |
| GET `/api/studio/render-config?scope=active` | 新的只读清单：kind、稳定 ID、页面数、指纹、内容路径。 |
| GET `/api/studio/themes/:id/html` | 只返回 text/plain + nosniff 原文，不在同源直接执行上传 HTML。 |
| GET `/reveal/` | 原副屏入口。Active 为 HTML 时返回受信宿主；CSS 时仍为原 Reveal。 |
| GET `/reveal/?studio=draft&studioTheme=...` | 原预览位置。HTML 草稿不注册 WS；CSS 草稿也防止参与正式联动。 |

原 `/studio/slides` 继续编辑 Markdown。HTML 模式下它的编辑预览固定使用原内置 CSS，不会把整份 HTML 与 Markdown 互相覆盖。

## HTML 控制接口

包内最终 HTML 已有 `window.ZhizhengFlow.goTo(零起始索引)`、`getState()` 和 `flow-data` JSON，无需手改集成开关。

其他开发者的多页 HTML 可提供显式 JSON 清单和控制 API：

```html
<script id="showflow-manifest" type="application/json">
{"format":"showflow-html/1.0","adapter":"showflow","pages":[{"id":"page-start","title":"首页"},{"id":"page-work","title":"工作环节"}]}
</script>
```

```js
window.ShowFlowPage = {
  async gotoById(id) { /* 在本 HTML 内切换；完成后返回 */ },
  getCurrentPageId() { /* 返回当前已显示的稳定 ID */ }
};
```

清单只是元数据，服务端不 eval，不提取执行任意脚本。未知 adapter、重复 ID、非法索引被拒绝。无接口 HTML 按单页提供明确提示。

## 运行与确认

可信宿主负责原 WebSocket，上传脚本只运行在 `sandbox="allow-scripts"` 的不透明来源 iframe。父子通信校验窗口来源与随机 token，子页面不能访问宿主 DOM 或存储；自包含资源在限定 CSP 中加载。生产宿主从 HTTP(S) 获取自己的 origin。测试使用 about:blank 不透明父页面，仅在该 origin 为 null 时子页面回报才使用通配 targetOrigin，窗口和 token 校验不变。

只有 HTML 返回的页面 ID、索引、页数与清单一致，且至少等待两个渲染帧后，才对原 NAVIGATE 回 ACK。重复 commandId 不重复跳页；未知 ID 回 ERROR。断线由原控制台的 SYNC_STATE 恢复，HTML 不创造第二套主控。

发布不强制实时画面跳页。已打开的 HTML 副屏发现新主题只提示更新，操作员在合适时机载入并刷新编排清单。首次从旧 Markdown 切换须手工绑定稳定 ID，本包不会自动假设新旧 16 页对应。

## 文件核对

`patch-manifest.json` 包含基准 ZIP 和各修改前/后 SHA256；`changes.diff` 供老师审核与人工合并。安装脚本只针对基准根源码，故意拒绝旧部署副本。`测试记录/核心原文件未变更校验.json` 列出已核对未改的核心文件。
