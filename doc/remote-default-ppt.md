# 远程上传并替换默认 PPT（打开即放映）

在「放映联动」（[presentation-link.md](./presentation-link.md)）基础上新增的能力：
从局域网任意电脑上传 `.pptx`，上传成功后立即成为服务端默认 PPT；已打开的播放页
自动加载新文稿并从第一页进入放映；刷新、重开浏览器、重启服务后仍播放最新默认 PPT。

## 一、访问路径

| 路径 | 页面 | 说明 |
| --- | --- | --- |
| `/` | 编辑器 | **原有界面，保持不变**：编辑 + F5 放映 + 主菜单「放映联动」设置 |
| `/play` | 播放页 | 打开即加载默认 PPT 并自动放映；右上角常驻「放映联动」「上传 / 更换 PPT」入口，可随时「打开编辑器」回到原界面 |
| `/upload` | 上传管理页 | 中文界面：上传并设为默认、查看当前默认信息、复制远程上传地址 |
| `/editor` | 编辑器 | 同 `/` |
| `?mode=audience` | 观众窗口 | 从播放页/放映工具栏打开，跟随主控显示 |

## 二、启动与部署

```bash
npm install
npm run build      # 构建前端（含类型检查）
npm run server     # 启动服务端（默认 http://0.0.0.0:8686），同时提供页面、API 与 SSE 通知
```

- **生产（推荐）**：以上两条命令即可。服务端单端口同源提供页面 + `/default-ppt-api/*`
  + SSE，无跨域问题；局域网其他电脑通过 `http://<服务器IP>:8686/upload` 访问上传页。
- **开发调试**：先 `npm run server`，再 `npm run dev`（Vite 已配置 `/default-ppt-api`
  代理到本地服务端，目标可用 `PPTIST_SERVER_ORIGIN` 覆盖）。
- **环境变量**（均有默认值）：

  | 变量 | 默认 | 说明 |
  | --- | --- | --- |
  | `PPTIST_PORT` | `8686` | 服务端口（绑定 0.0.0.0） |
  | `PPTIST_DATA_DIR` | `<项目>/data/default-ppt` | 默认 PPT 持久化目录 |
  | `PPTIST_PUBLIC_URL` | 空（用请求 origin） | 对外访问基地址，播放页/上传页展示上传地址用；建议设为 `http://<局域网IP>:8686` |
  | `PPTIST_MAX_UPLOAD_MB` | `100` | .pptx 大小上限 |
  | `PPTIST_KEEP_VERSIONS` | `5` | 保留的历史版本数 |
  | `PPTIST_DIST_DIR` | `<项目>/dist` | 前端产物目录 |
  | `PPTIST_REMOTE_API` | `https://server.pptist.cn` | /api 代理目标（AIPPT 等），置空禁用 |

- **Docker**：已提供 `Dockerfile` 与 `docker-compose.yml`，数据卷 `pptist-data` 挂载到
  `/app/data`，容器重建后默认 PPT 不丢失。部署时把 `PPTIST_PUBLIC_URL` 设为服务器实际
  局域网地址。

## 三、默认 PPT 的保存位置与方式

服务端目录（默认 `data/default-ppt/`，可用 `PPTIST_DATA_DIR` 调整）：

```
data/default-ppt/
├── current.json                  # 当前默认版本元数据（临时文件 + rename 原子写入）
└── versions/
    └── v<序号>/
        ├── raw.pptx              # 原始 .pptx 文件
        ├── slides.json           # 解析后的文稿数据（图片/GIF 为 base64 data URL，自包含）
        └── meta.json             # { seq, version, filename, pageCount, updatedAt }
```

- **原子切换**：新版本先完整写入独立目录，再原子替换 `current.json`；任一步失败
  旧默认不受影响，正在播放的页面不受影响。
- **版本顺序**：上传请求在服务端串行处理（按提交顺序），后提交者覆盖先提交者，
  版本号 `seq` 单调递增；同名文件重复上传也会生成新版本。
- **版本对应**：原始文件与解析数据同目录、同版本保存；播放端加载时以响应头
  `X-PPTist-Version` 为准，请求期间发生更新也不会错配。
- **历史清理**：仅保留最近 `PPTIST_KEEP_VERSIONS` 个版本；播放端加载后数据已在内存，
  清理不影响播放。
- **不上传者浏览器存储**：所有数据在服务端磁盘，任何电脑打开播放页都能获取。

## 四、上传与替换流程

1. 上传页选择/拖入 `.pptx` → 浏览器端用与编辑器**完全相同**的导入管线解析
   （`pptxtojson`，图片/GIF 内嵌 base64、保留演讲者备注，不是截图播放）。
2. 解析成功（非空文稿）后才可点击「上传并设为默认」；类型、大小、ZIP 魔数、
   非空文稿在浏览器与服务端双重校验。
3. 上传请求包含原文件（base64）+ 解析数据，服务端校验通过后原子切换为新版本，
   并通过 SSE（`/default-ppt-api/events`）立即通知所有播放端。
4. 任一步骤失败：明确提示失败原因，旧默认文件不变，正在播放的旧 PPT 不中断。
5. 播放端收到通知后：先在后台加载新文稿（加载期间继续显示旧 PPT），就绪后
   在页面内部切换：旧文稿发送 `presentation.ended`（最后停留页及备注）→ 新文稿
   从第一页发送 `presentation.started`；新文稿未就绪或加载失败绝不提前结束旧文稿。
6. 通知通道断线重连时，播放端会核对服务端当前版本，自动补上断线期间错过的更新；
   重复/过期通知按版本号忽略。
7. 观众窗口收到完整新文稿数据（不是只同步页码）。

内部版本号与更新通知仅走 SSE 通道；**对外四字段放映事件协议完全不变**
（`event/page/id/notes`，不加入版本号，不发布到业务 MQTT Topic）。上传新 PPT 也不会
重置 MQTT/WebSocket 连接配置。

## 五、打开即放映

- 播放页加载完成后直接进入放影视图（普通/演讲者视图可切换），从第一页开始；
  不显示编辑器、不加载示例 PPT、不弹「开始放映」对话框。
- **原生全屏**：与编辑器 F5 放映一致，播放页打开时会请求原生全屏；浏览器因缺少
  用户操作拒绝时（常见于刚打开的页面），会在首次有效交互（点击幻灯片区域、翻页笔、
  键盘按键）时再次尝试进入全屏。请求被拒绝不影响放映——页面始终铺满可视区，
  右上角保留「全屏」按钮可一键进入；播放页按 ESC 退出全屏不会结束放映。
  更换 PPT（热替换）后同样会自动恢复原生全屏。
- **60 秒自动全屏**：打开播放页 60 秒后仍未进入原生全屏（且此前从未进入过），会自动
  再次尝试进入；已处于全屏则不做任何处理。注意：浏览器要求 60 秒内至少有过一次
  点击/按键（任意交互即可），自动尝试才能成功。
- **大屏零交互全屏（推荐 kiosk 模式）**：浏览器安全机制要求至少一次用户操作才能进入
  原生全屏。若大屏开机后完全无人操作，建议用浏览器 kiosk 模式启动，实现真·全屏且
  无任何界面元素：
  ```
  chrome --kiosk http://<服务器IP>:8686/play
  msedge --kiosk http://<服务器IP>:8686/play
  ```
  也可设置开机自启该命令，实现"通电即放映"。
- 首次打开/刷新真正开始放映后才发送一次 `presentation.started`（page=1）；
  加载状态、占位数据不触发放映事件。
- 无默认 PPT 时显示「暂无默认 PPT」+ 上传地址 + 步骤说明，并持续监听更新；
  首次上传成功自动进入放映。播放页右上角有常驻「上传 / 更换 PPT」「放映联动」
  按钮，指引中显示完整上传地址（可复制），也可一键「打开编辑器」回到原界面，
  不中断当前放映。
- 播放页/上传页不发送放映事件（除播放页真实放映状态变化外）；上传页永不进入放映。

## 五点五、编辑器与播放页对齐

- 编辑器（`/` 与 `/editor`）启动时：若服务端已有默认 PPT，则**加载同一份文稿**
  （与大屏播放页内容一致，含主题、页面尺寸与演讲者备注）；服务端没有默认文稿或
  不可达时，回退为原有示例数据，编辑器其他行为不变。
- 在编辑器中 F5 放映的仍是编辑器当前内容（原有习惯）；要让大屏 `/play` 显示修改
  结果，把修改后的文件通过 `/upload`「上传并设为默认」即可。

## 六、验证

```bash
npm run type-check            # 类型检查
npm run build                 # 构建（含类型检查）
npm run test:presentation     # 放映联动 45 项（备注转换/状态机/热替换时序/双通道实测）
npm run test:default-ppt      # 服务端集成 9 项（校验/原子切换/SSE/顺序/清理/重启/SPA 回退）
npm run test:default-ppt:browser   # 浏览器端到端 12 项（需先 build；puppeteer 无头 Chrome）
```

三项测试当前全部通过。浏览器 E2E 实测内容：无默认 PPT 等待页 → B 上下文（模拟另一台
电脑）在 /upload 真实解析上传 → A 播放页自动放映并显示新内容 → started（page=1，多行
中文备注）经本地 WS 服务端捕获且恰为四字段 → 再上传 v2 → A 未刷新热替换 → 事件恰为
ended（旧稿）+ started（新稿第 1 页），无多余 slide.changed → 刷新后仍自动播放 v2 →
未进入原生全屏也正常放映 → 上传入口可见且地址正确 → /editor 正常。

**未实测项（需人工联调）**：真实跨物理电脑访问（当前以独立浏览器上下文模拟）、
大文件（接近上限）上传耗时、Docker 实机部署、GIF 动图在实际投影环境中的观感
（GIF 走未改动的 base64 data URL 渲染管线，自动化样例仅覆盖结构）。

## 七、简短使用步骤

1. 大屏电脑：`npm run build && npm run server`。
   - 想用原来的编辑器：打开 `http://localhost:8686/`（与原来完全一致，F5 放映、ESC 退出）。
   - 想用「打开即放映」的大屏模式：打开 `http://localhost:8686/play`。
2. 其他电脑：打开 `http://<服务器IP>:8686/upload`（播放页指引中会显示并支持复制）。
3. 选择 .pptx → 「上传并设为默认」→ `/play` 播放页自动切换到新 PPT 第一页并放映。
4. MQTT/WebSocket 放映联动设置：编辑器主菜单「≡ → 放映联动」，或播放页右上角「放映联动」按钮，两处是同一份配置。
5. 日常放映：大屏电脑重启后直接打开 `/play` 即可，无需其他操作；翻页仍由翻页笔/键盘控制
   （自动放映 ≠ 自动翻页，本功能不会开启自动翻页）。
