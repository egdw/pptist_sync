# PPTist 大屏部署包（RK3588 / Linux aarch64）

把做好的 PPT 变成「通电即放映」的大屏：板子上解压本包 → 执行一次 `./setup.sh` → 以后桌面双击「PPTist 大屏播放」即可。

## 包内容

| 文件/目录 | 说明 |
| --- | --- |
| `dist/` | 已构建好的 PPTist 前端页面（无需再编译） |
| `server/pptist-server.mjs` | PPTist 服务端（页面 + 默认 PPT 管理 + 更新通知） |
| `server/showflow-ws.mjs` | 多屏联动 WebSocket 服务（联动编排/副屏同步） |
| `server/node_modules/ws` | WebSocket 依赖（已随包捆绑，无需联网安装） |
| `reveal-example/` | 副屏 Reveal / Markdown 演示页（服务端在 /reveal 自动托管） |
| `runtime/node-v20.18.1-linux-arm64.tar.xz` | 自带的 Node.js 运行时（首次部署自动解压，无需联网） |
| `setup.sh` | 一键部署脚本（解压运行时、生成配置和桌面快捷方式） |
| `start-pptist.sh` | 启动服务并打开浏览器（可带参数 `play` / `editor` / `upload` / `showflow` / `secondary` / `reveal`） |
| `stop-pptist.sh` | 停止服务 |
| `enable-boot-service.sh` | 注册 systemd 服务、立即启动并设置真正的开机自启 |
| `disable-boot-service.sh` | 取消 systemd 开机自启（不会删除文稿和照片） |
| `logo.png` | 桌面快捷方式图标 |

## 首次部署（三步）

1. 把整个 `pptist` 目录拷贝到 RK3588 板子（U 盘 / scp 均可），建议放到家目录，例如 `/home/user/pptist`；
2. 在该目录打开终端执行 `bash setup.sh`（如需开机自动放映则执行 `bash setup.sh --autostart`；
   提示权限不足时先执行 `chmod +x *.sh`）；
3. 桌面双击 **「PPTist 大屏播放」** —— 服务自动启动，浏览器自动以全屏（kiosk）方式打开播放页。

> 需要 `xz` 命令解压自带运行时（多数系统自带；缺失时脚本会提示 `sudo apt install xz-utils`）。
> 若桌面环境没有 `~/Desktop` 目录（如中文系统为 `~/桌面`），脚本会自动识别。

## 日常使用

| 操作 | 方式 |
| --- | --- |
| 大屏放映 | 双击桌面「PPTist 大屏播放」（服务没启动会自动拉起） |
| 更换 PPT | 局域网任意电脑浏览器打开 `http://<板子IP>:8686/upload`，上传 .pptx 并点「上传并设为默认」，播放页 1 秒内自动切换 |
| 编辑文稿 | 双击应用菜单「PPTist 编辑器」或访问 `http://<板子IP>:8686/editor` |
| 停止服务 | 执行 `./stop-pptist.sh`（直接关机也无需额外操作） |

默认页面地址（端口可在 `config.env` 修改）：

- 播放页：`http://<板子IP>:8686/play`
- 上传页：`http://<板子IP>:8686/upload`
- 编辑器：`http://<板子IP>:8686/editor`
- 联动编排：`http://<板子IP>:8686/showflow`
- 副屏 PPTist：`http://<板子IP>:8686/secondary`
- 副屏 Reveal：`http://<板子IP>:8686/reveal`

## 多屏联动编排（Virtual Show Flow）

独立于 PPT 页码的"虚拟播放序列"：提前把主屏页面、副屏页面按演出顺序拖拽编排，
放映时只按 →/← 逐个执行虚拟步骤，主副屏各自跳转到正确页面（页数无需一致）。

**典型使用流程：**

1. 上传两份 PPT：打开 `/upload`，上传目标选「主屏文稿」传主屏 PPT；
   再把目标切到「副屏文稿（PPTist B）」传副屏 PPT（两份完全独立，页数可不同）。
2. 主控电脑打开 `/showflow` 编排页：左侧主屏页面池、右侧副屏页面池（带缩略图），
   点击或拖拽页面到中间序列，支持仅主屏 / 仅副屏 / 主副同步步骤；
   编排好的方案可「另存为」多份随时切换。
3. 副屏电脑打开 `/secondary`（PPTist B）或 `/reveal`（Markdown 流程图），
   页面会自动注册为副屏并等待控制。
4. 编排页打开「启用多屏联动」→ 点「开始联动放映」：主屏全屏放映，
   右下角迷你控制条显示当前步骤，按 →/← 逐步骤推进；副屏自动跟随并确认（ACK）。
5. 异常兜底：悬停迷你条可展开「重发 / 同步 / 强完 / 跳副 / 退出」等手动操作；
   若提示「控制台在其他窗口」，点「接管控制台」即可夺回控制权。

**注意：** 页面引用基于稳定 pageId（PPTist slideId / Reveal data-page-id），
源 PPT 增删页、调序后编排关系不乱；重新上传同槽位文稿后，在编排页点
「刷新副屏清单」会自动对账并提示变更。

## 配置（config.env）

首次执行 `setup.sh` 时自动生成，可手动编辑后重启服务：

```
PPTIST_PORT=8686                          # 服务端口
PPTIST_PUBLIC_URL=http://192.168.x.x:8686 # 对外访问地址（自动填入探测到的局域网 IP）
PPTIST_DATA_DIR=/home/user/pptist/data    # 主屏文稿保存位置
PPTIST_SECONDARY_DATA_DIR=.../data/secondary-ppt # 副屏文稿（PPTist B）保存位置，与主屏独立
# PPTIST_MAX_UPLOAD_MB=1024                 # 上传大小上限，默认 1GB，需要调整时取消注释
```

## 开机即放映

执行 `./setup.sh --autostart`，之后板子通电登录桌面时会自动启动服务并全屏打开播放页。
要求完全无人值守（不登录桌面直接全屏）时，可把浏览器 kiosk 命令注册为系统服务：
`chromium-browser --kiosk http://127.0.0.1:8686/play`。

## 后台服务开机自启（推荐）

在部署目录执行一次：

```bash
bash enable-boot-service.sh
```

脚本会请求 sudo 权限，自动创建 `/etc/systemd/system/pptist.service`，注册当前用户，
执行 `systemctl enable --now`。此方式不依赖用户登录桌面，机器启动后服务端即可供局域网访问。

常用管理命令：

```bash
sudo systemctl status pptist.service
journalctl -u pptist.service -f
sudo systemctl restart pptist.service
bash disable-boot-service.sh
```

systemd 服务只启动后端，不主动打开浏览器。需要开机后自动打开全屏浏览器时，另外执行
`bash setup.sh --autostart` 注册桌面登录后的 kiosk 入口。

## 常见问题

- **提示缺少 xz / tar**：`sudo apt install -y xz-utils` 后重新执行 `./setup.sh`。
- **双击桌面图标没反应**：先在终端执行 `./start-pptist.sh` 查看输出；确认当前用户在桌面会话中。
- **升级后页面仍显示旧版 / 100MB 上限 / 提示服务端版本较旧**：说明旧服务进程还占着端口。执行
  `pkill -f pptist-server.mjs; sleep 1; ./start-pptist.sh`，看到
  「服务就绪（新协议已生效，上传上限 1024MB）」即彻底解决（新版启动脚本每次启动会自动做这一步）。
- **其他电脑打不开上传页**：检查板子防火墙（`sudo ufw allow 8686` 或临时关闭），并确认与板子在同一网段；`config.env` 中 `PPTIST_PUBLIC_URL` 需为板子的实际局域网 IP。
- **浏览器不是全屏**：脚本已用 `--kiosk` 打开 Chromium 系浏览器；若使用 Firefox 则为 `--kiosk` 窗口全屏。也可用页面内右上角「全屏」按钮。
- **默认 PPT 存在哪里**：`pptist/data/default-ppt/versions/v<序号>/`（原始文件 + 解析数据 + 元数据），升级/重启不丢失；备份该目录即备份全部数据。
- **升级新版本**：用新版包整体覆盖（保留自己的 `data/` 目录与 `config.env`），然后执行 `./start-pptist.sh`（会自动清理旧进程）即可，数据不受影响。注意 `dist/`（页面）与 `server/`（服务端）必须来自同一个版本的包，两者配套升级。
